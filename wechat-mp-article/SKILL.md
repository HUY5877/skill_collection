# 微信公众号文章排版助手

把用户给的文章草稿，加工成一套可直接发布的公众号产出：**WeMD 格式正文 + 摘要文件 + 封面（图片或生图提示词）**，统一放进一个文件夹。

目标编辑器是 [WeMD](https://edit.wemd.app/)，正文必须符合它支持的 Markdown 语法。

## 输入

用户会提供一段文章内容（草稿）。可能在 `$ARGUMENTS` 里，也可能直接粘在对话中。

$ARGUMENTS

## 执行流程

按顺序执行，不要跳步。

### 1. 确认输出位置

用 AskUserQuestion 问用户想把成品文件夹生成到哪里，**默认选项为「桌面」**（推荐项放第一个）。其他可选：当前目录、用户自定义路径。

- 桌面路径按操作系统判断：Windows 一般为 `%USERPROFILE%\Desktop`（可能是 OneDrive 下的 Desktop），macOS/Linux 为 `~/Desktop`。拿不准就先探测。
- 文件夹名用文章标题（清理掉不能做文件名的字符）；没有明确标题就根据主题起一个简短的。

### 2. 优化内容与排版

在**不改变文章大致内容和作者原意**的前提下，做加工：

- 顺语序、改错别字、理清段落结构，让逻辑更顺。
- **保留作者的个人语气和口头表达**（口语、玩梗、自嘲、语气词等），不要改写成端着的官方腔。
- ==AI 味不要太重==：避免「总而言之/综上所述/值得注意的是」这类套话、避免过度排比和空洞铺陈、避免堆砌 emoji。
- 按 `references/wemd-syntax.md` 的语法把正文转成 WeMD 格式，并合理用上它的特性（提示块、表格、代码块、高亮等）让排版更清晰。
- 转换时务必遵守里面的**微信平台注意事项**（尤其：外部链接在公众号正文里点不动，改用纯文本/行内代码展示网址；表格列数别太多，照顾手机端）。

产出写入输出文件夹里的正文文件，如 `文章.md`。

### 3. 生成摘要

生成一条**不超过 50 字**的中文摘要，风格与文章一致、不浮夸。写入输出文件夹里的 `摘要.txt`。

### 4. 封面配图（关键：区分能否生图）

先判断**当前 agent 是否具备生图能力**（是否接入了任意可用的文生图工具 / MCP / 模型接口——不限定任何具体服务商）。

- **能生图**：读取 `references/cover-prompt.md` 里的封面提示词模板，把其中的「画面内容」和「风格」两处结合本篇文章主题填好，然后**用你自己现有的生图方式**生成封面，图片保存到输出文件夹（如 `封面.jpg`）。
- **不能生图**：把填好主题的最终提示词写入输出文件夹里的 `生图指令.txt`，并在流程结束时把这段提示词也展示给用户，让他自己拿去生成。

> 生图的**具体实现方式由各自 agent 决定**，本 skill 不规定、也不依赖任何特定生图服务商、接口或密钥。

### 5. 汇总产出

最终文件夹应包含：

- `文章.md` —— WeMD 格式正文
- `摘要.txt` —— ≤50 字摘要
- `封面.jpg`（能生图时） 或 `生图指令.txt`（不能生图时）

向用户报告：文件夹路径、生成了哪些文件；不能生图时附上生图提示词全文。

## 通用性与保密规则（重要）

- 本 skill 必须保持**通用**：不得写入或依赖任何特定生图服务商、API 路径、网关、Token 或任何公司内部/保密信息。
- 生图能力的有无与实现，完全交给运行本 skill 的 agent 环境自行决定。
- 不要臆造下载链接或结果；没有生图能力就老实走「输出提示词」这条路。
